# Wayfinder Map: Trellis MVP Architecture & Build Roadmap

## Destination

A complete, working, role-aware agentic RAG workspace built by a 3-person team in 3 months. Features strict hierarchical access control (documents accessible only to the owning role and above; zero cross-team data leakage), an agentic RAG chatbot enforcing scope at the retrieval/tool layer, role-scoped dashboards, and an admin console for org/role configuration.

## Notes

- **Team**: 3 B.Tech CSE seniors (1 Frontend, 1 Backend+DB, 1 Agentic Workflows & System Architecture/Lead)
- **Timeline**: 3 months
- **Tracker**: Local Markdown (`.scratch/trellis/issues/`)
- **Key Skills to Consult**: `domain-modeling`, `grilling`
- **Core Architectural Invariant**: Never trust the LLM or frontend for security. Access scope resolution (`resolve_scope()`) happens strictly in the database/backend layer. The LLM calls typed tools with server-injected `AccessScope` — it never receives or manipulates the scope itself.
- **Backend Dev lane**: Owns Clerk JWT middleware (`app/core/auth.py`), `get_scope` dep (`app/core/deps.py`), scope resolver (`app/scope/resolver.py`), all FastAPI routers, Pydantic schema contract, and the `openapi-typescript` codegen pipeline. Coordinates with Frontend Dev on the typed client and with Agentic Lead on the `AccessScope` interface injected into LangGraph tools.

## Decisions so far

- [01-lock-core-tech-stack](./issues/01-lock-core-tech-stack.md): **Next.js + FastAPI + NeonDB (pgvector) + Clerk.** Python backend is non-negotiable for LangGraph/pgvector ecosystem. OpenAPI → `openapi-typescript` generates typed client for Next.js.
- [02-database-schema-hierarchical-rbac](./issues/02-database-schema-hierarchical-rbac.md): **Hybrid Role + Team model.** Roles are global to the org (tree, `parent_role_id`). Team membership stores a `role_id` per user per team — same user can be "Manager" in Team Alpha and "Employee" in Team Beta. Document access rule: a doc tagged to Role R is visible to R and all ancestors of R. A doc tagged to a Team is visible to all team members and all roles hierarchically above the team. **⚠️ CTE CORRECTED (2026-09-21):** Recursive vector search walks DOWN the tree (`r.parent_role_id = vr.id`) to find descendants — a logged-in HR user sees docs tagged to HR, Manager, and Employee (roles they govern), not Admin.
- [03-scope-resolution-engine](./issues/03-scope-resolution-engine.md): `resolve_scope(user_id, org_id)` — note: org_id required for multi-org. Returns `AccessScope` (visible_role_ids, allowed_team_ids, permissions_by_team). Auth: `PyJWT` + `cryptography` via `PyJWKClient` verifying Clerk JWTs. Cache: `cachetools.TTLCache` in-memory (max 1000, 5-min TTL) for MVP — no Redis setup needed. Explicit invalidation on role or team membership changes.
- [Embedding model decided]: `mxbai-embed-large-v1` (1024 dims). Open source, free embedding model. Schema column is `Vector(1024)`. Ingestion calls HuggingFace Inference API to save backend RAM.
- [File storage decided]: **UploadThing**. Direct browser/frontend uploads. FastAPI only receives the final CDN `file_url` string in DB (never processes raw file bytes).
- [Database migrations]: **Alembic** manages schema migrations for NeonDB. Direct URL for migrations, pooled URL for FastAPI async runtime.
- [04-agentic-rag-graph-design](./issues/04-agentic-rag-graph-design.md): *(Topology superseded by ticket 10; guardrails, tools, SSE event types and checkpointer still valid.)* **ReAct agentic loop** (not a hardcoded deterministic graph) with structural guardrails: 8-call step budget, Pydantic tool schema enforcement, server-injected `AccessScope` (LLM never sees or manipulates scope), loop detection, query rewrite capped at 2, groundedness check before synthesis. Tools: `search_documents`, `get_tasks`, `get_team_summary`, `create_task`, `give_strike`, `give_commendation`. SSE event schema locked: `status`, `tool_call`, `token`, `citations`, `error`, `done`. Memory via `AsyncSqliteSaver` keyed by `{org_id}:{user_id}:{session_id}` — multiple named threads per user, visible to that user only. Migration to `AsyncPostgresSaver` (NeonDB) is a one-line swap.
- [10-langgraph-graph-code-structure](./issues/10-langgraph-graph-code-structure.md): Node contracts & execution topology locked. Pre-graph Guardrails AI filter; 3-way Router (`conversational`, `retrieve`, `write`); "Retrieve inside Write" for compound queries; pgvector HNSW (`<=>`) & typed relational tools (`get_tasks`, `get_team_summary`); 2x rewrite budget with Plain LLM refusal escape hatch; `@mention` entity disambiguation; HITL Pattern A (Conversational confirmation) for strikes.
- [11-document-ingestion-pipeline](./issues/11-document-ingestion-pipeline.md): **scope_type ENUM extended to `org` | `role` | `team`** — org-scoped docs visible to all org members via `WHERE scope_type='org' AND org_id=:org_id`. Documents schema gains `file_url`, `file_type`, `status` (processing/ready/failed), `chunk_count`. Ingestion: async FastAPI BackgroundTask, 202 Accepted immediately, frontend polls status. Extractors: `pymupdf` (pdf), `python-docx` (docx), `python-pptx` (pptx, text per slide), native string (txt/md). Chunking: RecursiveCharacterTextSplitter (1000 chars / 200 overlap for docs; 500 chars / 100 overlap for pptx). Embeddings: HuggingFace Inference API batch 16–32, `mxbai-embed-large-v1`. Chunks denormalized with org_id, scope_type, role_id, team_id for zero-JOIN vector search.
- [08-chat-session-management](./issues/08-chat-session-management.md): **Chat sessions architecture resolved.** NeonDB `chat_sessions` table (`id`, `org_id`, `user_id`, `title`, timestamps) stores session metadata; LangGraph checkpoints live separately in `checkpoints.db` (SQLite) keyed by `{org_id}:{user_id}:{session_id}` for strict org isolation. 5 CRUD endpoints (`/api/v1/chat/sessions`). Auto-title from first 60 chars of first message (editable via PATCH). Hard delete purges both Postgres row and SQLite checkpoint blobs. FastAPI `lifespan` pattern manages checkpointer startup/shutdown cleanly.
- [05-api-contract-and-type-gen](./issues/05-api-contract-and-type-gen.md): **FastAPI OpenAPI contract & Next.js codegen locked.** Full Pydantic schemas defined in `schemas.py` for auth (`/api/v1/auth/me`, `/api/v1/auth/context`), org onboarding, role hierarchy (flat list with depth, standalone permissions, re-parenting via `PATCH /api/v1/admin/roles/{id}`), team membership & invitations (`invitations` table tracking pending invites + Clerk invite integration), documents, tasks & submissions, strikes & commendations, and polymorphic dashboard metrics. Next.js runs `api:generate` (`openapi-typescript` → `frontend/lib/api/v1.d.ts`, see frontend-scaffold/03) for 100% type safety. *Endpoint list provisional; schemas locked.*
- [Permission actions decided]: `create_role`, `create_team`, `add_member`, `upload_document`, `assign_task`, `give_strike`, `view_aggregate`, `review_strike`.
- [06-admin-role-hierarchy-ui](./issues/06-admin-role-hierarchy-ui.md): Resolved via [frontend-scaffold/06](../frontend-scaffold/issues/06-admin-console-architecture.md) — `/admin/*` sub-routes, read-only React Flow + Dialog editors, two-step UploadThing tagging (Org / Role / Team).
- [12-D1 AccessScope placement](./issues/12-decision-reconciliation.md): **Runtime context, not state.** `AccessScope` is a frozen value object (`in_team()`, `can()`), resolved per request by `get_scope`, and passed to LangGraph via `context=AgentContext(scope, audit_id)`. It is never checkpointed and never in LLM tool schemas. Enforcement sits in shared data-access functions that require `scope`, used by both REST endpoints and agent tools. Details: ticket 03 §1/§1a/§6.
- [12-D2 Chat endpoint](./issues/12-decision-reconciliation.md): **`POST /api/v1/chat/sessions/{session_id}/message`** is the single chat endpoint and returns the SSE stream. `/chat/stream` is retired. BFF proxy: `app/api/chat/sessions/[sessionId]/message/route.ts`. The REST endpoint list overall is still provisional (D3).
- [12-D3 API prefix](./issues/12-decision-reconciliation.md): **Every FastAPI route lives under `/api/v1`**; `/health`, `/docs` and `/openapi.json` stay at the root. `v1` is a fixed label and no `v2` is planned for the MVP: the only client is our own BFF, and breaking changes are caught by `api:generate` plus the CI diff. Next.js BFF routes (`/api/...`, called by the browser) are separate and unversioned.
- [12-D8 Identity pipeline](./issues/12-decision-reconciliation.md): **Clerk proves identity; the Trellis DB decides permissions.** The chain is `verify_clerk_jwt` (RS256, `iss`, `azp`) → `get_identity` (JIT user) → `get_org_context` (Clerk org → `organizations.id`, 409 if not provisioned, JIT membership, apply pending invitations) → `get_scope`. Identity comes only from the token; the BFF sends only the Bearer token, with no `X-*` headers. Details: ticket 03 §2 and §5.
- [12-D9 Org-level role](./issues/12-decision-reconciliation.md): `org_members.role_id` holds an org-wide role alongside the per-team roles. `AccessScope.org_permissions` + `can_org()`; `can(p, team)` = org role OR team role. Each org gets a seeded protected root `Admin` (`is_system`, all 8 permissions) for its creator. **No privilege escalation:** users act only on roles strictly below their own and grant only permissions they hold.
- [12-D10 Onboarding](./issues/12-decision-reconciliation.md): Self-serve org creation in Clerk → `/onboarding` → idempotent `POST /api/v1/orgs/provision` (org + Admin role + creator membership in one transaction). The Trellis backend is the only writer of memberships (Clerk API first, then DB). Invitations: Trellis row = what they get, Clerk = delivery, applied on the invitee's first request. No webhooks in the MVP (v2 drift repair).
- [12-D4 Admin console](./issues/12-decision-reconciliation.md): Trellis RBAC only, no Clerk-role gate. Entry: `can_org("create_role") or can_org("add_member")`. Each tab checks its own permission: Roles `create_role`; Teams `add_member`/`create_team`; Documents `upload_document`; Strikes `review_strike`. The frontend gate only affects what users see; the backend enforces every action.
- [12-D15 Org creation](./issues/12-decision-reconciliation.md): **D10/D4 kept.** Explicit `POST /api/v1/orgs/provision` from `/onboarding` (a pass-through on the way to `/dashboard`); members are managed by holders of `add_member`/`create_role`, not only the creator.
- [12-D13 Team visibility](./issues/12-decision-reconciliation.md): You see a team if you are on it, or if **every** member ranks strictly below one of your roles. Admin and HR see all the teams under them; a manager does not see a peer manager's team. Writes still need `can(p, team)`.
- [12-D16 Error shape](./issues/12-decision-reconciliation.md): Every Trellis error is `{"detail": {"code", "message"}}` (`app/core/errors.py::api_error`). The BFF redirects on `invalid_token` / `no_active_org` / `org_not_provisioned` and shows `detail.message` in a sonner toast for everything else.
- [12-D17 Role creation yardstick](./issues/12-decision-reconciliation.md): "Strictly below the caller" is measured from the caller's **org-level role only**; role endpoints need `can_org("create_role")`; new roles always have a parent at or below the caller's role; granted permissions ⊆ the caller's org permissions.
- [Strike system]: Strike highlights to direct manager (role immediately above in team). Threshold (3 strikes) escalates to next level up. Commendation system (`give_commendation`) included in MVP as positive counterpart — same hierarchy check, no RAG validation needed.
- [Org provisioning flow — decided 2026-09-28]: **Superseded 2026-10-08 by [12-D15](./issues/12-decision-reconciliation.md): D10/D4 kept.** Original text: **Clerk is source of truth (Option A).** User creates org via Clerk on the frontend → Clerk issues `clerk_org_id` → backend mirrors it into `organizations` table on first JWT hit for that org. Backend does NOT auto-create org rows — creation is always user-initiated via Clerk. Only the org creator (admin) can add/remove members and assign roles.
- [User auth redirect flow — decided 2026-09-28]: Returning user → redirected to last active org workspace (org switcher available on that page). New user with no org → redirected to "Create Organization" page. New user who has been invited by an admin (TeamMember row exists) → redirected directly to their org workspace. Frontend drives all redirect logic based on the `org_id` presence in the Clerk JWT and the user's `AccessScope`.

## Not yet specified

- **Dynamic Access Escalation**: `request_access(topic, reason)` workflow — user requests access to out-of-scope document, triggers notification to manager/admin for approval. Deferred from MVP (zero-result refusal is the safe v1 behavior); kept here for v2 graduation.
- **Scoring & Evaluation Suite**: Red-teaming benchmark and automated prompt injection defense testing.
- **Real-time vs. polling**: WebSocket vs. SSE vs. short-polling for live task/notification updates (chat streaming is SSE; this is about dashboard/task status refresh).
- **Document versioning**: What happens to vector chunks when an SOP document is updated? v1 default: re-upload creates a new document record; Admin deletes old one manually (cascade deletes chunks).
- **Strike appeal flow**: Employee disputes a strike → flagged to HR / `review_strike`-permissioned role.
