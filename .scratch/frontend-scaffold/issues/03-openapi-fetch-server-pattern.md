# 03 — openapi-fetch Server-Only Client Pattern
Type: research
Status: resolved

## Question

How is `openapi-fetch` correctly configured for server-only use in Next.js App Router (BFF pattern)?

Specifically:
- How is the typed client instantiated and where does it live (singleton module, per-request factory)?
- How is the Clerk JWT injected into every request as the `Authorization` header, given that `auth()` is async and request-scoped?
- How does the client work inside a Server Component vs. inside a Route Handler (for SSE streaming)?
- Are there any Next.js 16 / React 19 caveats (e.g., `cache()`, `connection()`) that affect how the client should be set up?
- What does the code-generation step look like (`openapi-typescript` CLI, output location, CI hook)?

## Answer

### 1. Singleton Module Pattern — the correct choice

Use a singleton `createClient<paths>({ baseUrl })` exported from `lib/api/client.ts`. The client is **stateless** — it does not hold session data. Request-scoped auth is injected via `openapi-fetch`'s middleware `onRequest` hook, which runs lazily per-call inside the active `AsyncLocalStorage` context, so there is zero cross-request token leakage.

**Do NOT** use `cache()` on the client factory — `cache()` should wrap your **data-fetching query functions**, not the client instantiation.

---

### 2. Singleton client with Clerk auth middleware

```typescript
// lib/api/client.ts
import 'server-only';
import createClient, { type Middleware } from 'openapi-fetch';
import { auth } from '@clerk/nextjs/server';
import type { paths } from './v1'; // generated by openapi-typescript

const authMiddleware: Middleware = {
  async onRequest({ request }) {
    // Allow explicit override (machine-to-machine calls)
    if (request.headers.has('Authorization')) return request;

    try {
      const { getToken } = await auth();
      const token = await getToken();
      if (token) {
        // ONLY the token. The active org, user and org role are all inside it, and FastAPI
        // derives identity from the verified token alone (trellis ticket 12 D8).
        // Do NOT add X-Org-Id / X-User-Id / X-Org-Role headers.
        request.headers.set('Authorization', `Bearer ${token}`);
      }
    } catch {
      // No active request context (static gen, public edge)
    }

    return request;
  },
};

export const api = createClient<paths>({
  baseUrl: process.env.FASTAPI_INTERNAL_URL ?? 'http://127.0.0.1:8000',
});

api.use(authMiddleware);

// For public/webhook routes that don't need auth
export const publicApi = createClient<paths>({
  baseUrl: process.env.FASTAPI_INTERNAL_URL ?? 'http://127.0.0.1:8000',
});
```

**Deduplication of data fetches** — wrap DAL query functions in `cache()`:

```typescript
// lib/api/queries/documents.ts
import 'server-only';
import { cache } from 'react';
import { api } from '@/lib/api/client';

export const getDocuments = cache(async () => {
  const { data, error } = await api.GET('/api/v1/documents');
  if (error) throw new Error(JSON.stringify(error));
  return data;
});
```

### 3. Route Handler for SSE streaming (BFF proxy)

Use `parseAs: 'stream'` to skip buffering and pipe `ReadableStream` directly to the browser:

```typescript
// app/api/chat/sessions/[sessionId]/message/route.ts   (path updated 2026-10-08, trellis/12 D2)
import 'server-only';
import { NextRequest, NextResponse } from 'next/server';
import { api } from '@/lib/api/client';

export const dynamic = 'force-dynamic';
export const runtime = 'nodejs';

export async function POST(
  req: NextRequest,
  { params }: { params: Promise<{ sessionId: string }> },
) {
  const { sessionId } = await params;
  const body = await req.json();

  const { response, error } = await api.POST('/api/v1/chat/sessions/{session_id}/message', {
    params: { path: { session_id: sessionId } },
    body,
    parseAs: 'stream',
  });

  if (!response.ok || !response.body) {
    return NextResponse.json(
      { error: error ?? 'Agent stream unavailable' },
      { status: response.status || 500 }
    );
  }

  return new Response(response.body, {
    status: 200,
    headers: {
      'Content-Type': 'text/event-stream; charset=utf-8',
      'Cache-Control': 'no-cache, no-transform',
      Connection: 'keep-alive',
      'X-Accel-Buffering': 'no', // prevents Nginx/Vercel proxy buffering
    },
  });
}
```

### 4. Code-generation workflow

```bash
# Generate types from live FastAPI dev server
npx openapi-typescript http://127.0.0.1:8000/openapi.json -o ./lib/api/v1.d.ts

# Or from exported JSON (no running server needed — commit openapi.json)
npx openapi-typescript ../backend/openapi.json -o ./lib/api/v1.d.ts
```

**File layout:**
```
frontend/lib/api/
+-- v1.d.ts         ? generated (commit to git)
+-- client.ts       ? singleton + Clerk middleware
+-- queries/        ? cache()-wrapped domain fetchers
```

**package.json scripts:**
```json
{
  "scripts": {
    "api:generate": "openapi-typescript http://127.0.0.1:8000/openapi.json -o ./lib/api/v1.d.ts",
    "api:generate:file": "openapi-typescript ../backend/openapi.json -o ./lib/api/v1.d.ts"
  }
}
```

**CI freshness check (GitHub Actions):**
```yaml
- name: Verify API types in sync
  run: |
    pnpm --filter frontend api:generate:file
    git diff --exit-code frontend/lib/api/v1.d.ts
```

### 5. Next.js 16 / React 19 caveats

- **`import 'server-only'`** at the top of `client.ts` — build fails immediately if a Client Component imports it. Non-negotiable guard.
- **Never** mutate `client.defaults.headers` — always use the `onRequest` middleware approach. Defaults are shared across all concurrent requests.
- **Next.js 15+ fetch defaults to `no-store`** — correct for authed BFF calls. For cacheable lookups, pass `next: { revalidate: 3600 }` per-call.
- **`await connection()`** — use in Server Components that call public FastAPI endpoints to opt out of Partial Prerendering and ensure fresh data.

## As built 2026-10-08 (Piyush): use this, don't rebuild it

**Files in `frontend/lib/api/`**
- `client.ts`: the `api` singleton with the Clerk token middleware, as in §2. `publicApi` was dropped because the MVP has no webhooks.
- `errors.ts`: `unwrap(api.GET(...))` returns the data or:
  - **redirects** on `invalid_token` → `/sign-in`, `no_active_org` → `/org-selection`, `org_not_provisioned` → `/onboarding`;
  - **throws `ApiError`** (`status`, `code`, `message`) for every other error. Show `err.message` in a sonner toast.
  - If the backend is unreachable, it throws `ApiError` with code `backend_unavailable`.
- `queries/auth.ts`: `getMe()` and `getAuthContext()`, both `cache()`-wrapped. `getAuthContext().active_org` drives navigation and the admin-console gate.
- `v1.d.ts`: generated. Never edit it by hand.

**Writes from browser forms (decided 2026-10-09, trellis/12 D18)**
- Server Actions in `lib/api/actions/<area>.ts` (`'use server'`). **Reference example (built 2026-10-09): `actions/roles.ts::createRole`**; read side `queries/roles.ts::getRoles`. Copy these for new areas.
- They call `api.POST/PATCH/DELETE` and **return** `{ ok: true, data } | { ok: false, message }` instead of throwing, so the dialog can toast `message` (Next.js hides thrown error messages in production). Redirect codes still redirect.
- On success: `revalidatePath('/admin/roles')` (or the page that changed).

**How to update the types**
- The backend owner runs `uv run python scripts/export_openapi.py` in `backend/` and commits `backend/openapi.json`.
- After pulling, run `pnpm api:generate` (reads that file) and commit `lib/api/v1.d.ts`.
- `pnpm api:generate:live` reads a running backend at `127.0.0.1:8000` instead.

**Backend URL**
- `FASTAPI_INTERNAL_URL` in `frontend/.env`. It defaults to `http://127.0.0.1:8000` when unset.
